项目采用「协议入口 → 核心调度 → 工具实现 → 存储后端」的分层结构：
- 入口层：`server.py` 提供基于 Python stdlib 的 HTTP Server（/schemas、/mcp、/health），`mcp_stdio_server.py` 提供 JSON-RPC 2.0 over stdio 的 MCP 服务器，两者都通过 `cloud.server.mcp_server.CNAA_MCPServer.handle_tool_call()` 路由到具体工具。
- 核心层：`cnaa/` 集中定义 13 个工具的元数据、输入 Schema、权限映射与安全认证（API Key + Bearer Token），并通过 `get_all_schemas()` / `get_tool_definitions()` 对外暴露契约。
- 存储层：`cloud/storage/` 提供内存与持久化状态存储，`local/memory/` 与 `local/state/` 提供本地即时记忆与状态缓存，`cloud/agent.py` 与 `local/agent.py` 分别作为云端与本地的 Agent 实现。
- 启动装配：`create_server()` 从环境变量加载 `AuthConfig`，注入 `CNAARequestHandler.auth_config` 并构造 `CNAA_MCPServer(auth_config=...)`，完成认证配置向工具链的透传。
- 测试与示例：`tests/` 覆盖生命周期、模型、MCP stdio、OpenClaw 集成等场景；`examples/openclaw_integration.py` 演示外部框架接入方式。
