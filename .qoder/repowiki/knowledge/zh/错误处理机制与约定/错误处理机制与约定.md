该仓库采用分层捕获加结构化响应的错误处理策略，没有定义统一的异常类型或全局中间件，而是通过各层入口的 try/except 块将异常转换为标准化的 JSON 响应。

HTTP 层使用 Python 标准库 http.server，在 _handle_mcp 中用 try/except json.JSONDecodeError 和 except Exception as e 分别处理解析失败与未预期异常，统一通过 _send_error(HTTPStatus, message) 返回包含 status 和 message 字段的错误对象。

stdio 层实现 JSON-RPC 2.0 协议，对 json.JSONDecodeError 返回 -32700 Parse error，对其他异常返回 -32603 Internal error，遵循 JSON-RPC 错误码规范。

工具路由层的 handle_tool_call 对所有 handler 调用包裹 try/except Exception，记录 logger.exception 后返回包含 status 和 message 的错误响应；未知工具直接返回 status 为 error 的响应。

安全模块在配置解析失败时记录 logger.error 并回退到默认值，如权限降级为 read_write，不抛出异常。

关键文件包括 server.py 作为 HTTP 请求入口集中处理 JSON 解析错误、认证失败、通用异常；mcp_stdio_server.py 作为 stdio MCP 服务器按 JSON-RPC 2.0 规范返回错误对象；cloud/server/mcp_server.py 负责工具路由与处理器统一捕获业务逻辑异常；cnaa/security.py 处理认证配置加载与权限校验失败时记录日志并降级。

所有错误以字符串消息形式向上冒泡由最外层捕获并格式化。HTTP 层始终返回包含 status 和 message 字段的标准化格式；stdio 层遵循 JSON-RPC 2.0 的 error 对象结构。配置解析失败应记录错误并回退到安全默认值保证服务可用性。HTTP 层必须通过 _send_error 发送错误响应禁止直接 raise 未捕获异常。认证失败必须返回 UNAUTHORIZED 状态码而非 500。
