本仓库未采用外部配置文件（如 .env、yaml、toml）或专用配置框架，而是通过 Python dataclass 与构造函数参数在代码内声明式地定义和注入运行时配置。整体呈现“无文件、无环境变量”的轻量配置模式。

1. 使用的系统与工具
- 使用标准库 dataclasses 定义配置结构体（如 LifecycleConfig），并通过构造函数参数注入到组件实例中。
- 命令行入口 server.py 使用 argparse 提供 --host、--port 两个启动参数，作为 HTTP 服务器的唯一外部配置点。
- 依赖管理集中在 pyproject.toml，仅声明运行时依赖（mcp>=1.0.0）与开发依赖（pytest、mypy、ruff），不包含应用级配置项。

2. 关键文件与位置
- cnaa/lifecycle.py：LifecycleConfig dataclass 定义生命周期阈值（max_active_memories、condensation_threshold、eviction_threshold、promotion_score_threshold），TimeBasedLifecyclePlugin 默认实现读取这些阈值。
- server.py：HTTP Server 入口，通过 argparse 暴露 --host/--port 参数，create_server() 接收并传入 host/port。
- local/agent.py：LocalAgentInterface.__init__ 接受 cache_ttl_minutes 等构造参数，用于本地状态缓存 TTL。
- cloud/server/mcp_server.py：CNAA_MCPServer.__init__ 接受 memory_store/state_store 后端实例，属于运行时依赖注入而非配置文件。
- pyproject.toml：项目元数据与依赖声明，不含应用配置段。

3. 架构与约定
- 配置即数据结构：所有可调参数以 dataclass 字段形式集中声明，默认值即为“开箱即用”的配置基线。
- 配置即依赖注入：组件通过构造函数参数接收配置对象或具体值，避免全局单例或隐式环境读取。
- 分层配置来源：
  - 进程级参数：server.py 的 --host/--port 由 argparse 解析。
  - 模块级默认值：LifecycleConfig、StateCache TTL 等在 dataclass 或函数签名中给出默认值。
  - 运行时注入：MCP Server 的存储后端、Local Agent 的 cache_ttl_minutes 等通过调用方传入。
- 无外部配置加载器：未发现任何 os.environ、dotenv、configparser、pydantic-settings 等用法，也不存在 .env、*.yaml、*.json、*.ini 等配置文件。

4. 约定与约束
- 所有可配置阈值必须通过 dataclass 字段显式声明并提供合理默认值（见 LifecycleConfig）。
- 组件不应直接读取环境变量或外部文件；如需外部化，应通过构造函数参数注入。
- 服务器启动参数统一通过 argparse 暴露，并保持最小集合（当前为 host、port）。
- 测试场景下通过构造时注入 mock 后端（如 set_mock_handler）替代真实服务，保持配置与实现解耦。

该设计使配置完全内联于代码，适合小型框架与示例工程；若需多环境部署或动态配置，可在不改变接口的前提下引入配置加载层并继续通过构造函数注入。
