# 三层 State 模型区分偏好、知识与环境上下文

_来源：461fe1c → 966265f 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
Agent 的状态管理需要区分不同重要性和用途的数据：用户偏好是长期稳定的，知识沉淀是短期可变的，环境上下文是动态变化的。混在一起会导致状态污染和更新策略混乱。

## 决策驱动
- 数据重要性分层
- 更新频率差异
- 生命周期管理
- 语义清晰度

## 备选方案
- **Preference + State + Environment 三层** — 优点：语义清晰、更新策略独立、便于按类别管理生命周期
- **扁平化单表存储** _（已否决）_ — 优点：实现简单；缺点：无法区分数据重要性、更新策略不灵活、查询效率低
- **基于标签的分类** _（已否决）_ — 优点：灵活性高；缺点：缺乏强制约束、容易滥用、查询复杂

## 决策
采用 Preference（重要记忆沉淀，含 importance 和 source_memory_ids）、State（知识沉淀，category 区分 KNOWLEDGE/PREFERENCE/ENVIRONMENT）、Environment（环境上下文）三层结构，每层有独立的接口和生命周期管理。

## 影响
State 演化逻辑更清晰，Preference 识别和 State 合并策略可以独立实现；但增加了数据模型的复杂性，需要确保三层之间的一致性。
