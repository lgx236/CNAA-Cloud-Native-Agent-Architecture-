项目采用三层正交架构：cnaa 包作为核心规范与接口契约层，定义 Experience Runtime Framework 的数据模型、JSON Schema 契约与抽象交互接口；cloud 子模块作为单一状态中心的 CNAA Server（MCP Server），将记忆与状态操作路由至可插拔存储后端；local 子模块作为多实例共享状态的本地 SDK（MCP Client + 即时记忆管理），封装对云端的持久化读写。三者通过 MCP 结构化 JSON 请求-响应对通信，形成「Agent(MCP Client) → CNAA Server(MCP Server) → 存储插件」的单向调用链。docs 子模块同步维护中英双语架构规范与 API 参考，与代码保持版本一致。
