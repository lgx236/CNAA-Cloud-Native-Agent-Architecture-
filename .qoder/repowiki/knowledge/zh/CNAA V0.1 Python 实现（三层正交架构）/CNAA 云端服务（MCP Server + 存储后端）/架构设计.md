模块采用三层正交结构：`server/mcp_server.py` 中的 `CNAA_MCPServer` 作为单一状态中心，依据 `cnaa.tools` 中定义的工具名注册 `_handle_*` 处理器，统一走 `handle_tool_call` 分派；`storage/` 下的 `InMemoryMemoryStore` 与 `InMemoryStateStore` 分别实现 `MemoryInterface` 与 `StateInterface` 两个抽象接口，被 Server 在构造时注入，形成“Server → 存储后端”的解耦；`agent.py` 的 `CloudAgentInterface` 是对 MCP Server 的 Python 方法封装，所有方法内部都通过 `server.handle_tool_call` 调用对应工具名（如 `cnaa_store_memory`、`cnaa_update_state` 等），从而保证 Python 直调与 MCP 协议调用共享同一套工具契约。`__init__.py` 仅暴露 `CNAA_MCPServer` 与 `CloudAgentInterface` 作为对外入口，隐藏内部存储实现细节。
