顶层 server.py 作为唯一进程入口，使用 Python 标准库 http.server 启动 HTTPServer，将 /schemas、/mcp、/health 三个路由分别委派给 cnaa.schemas.get_all_schemas() 和 cloud.server.mcp_server.CNAA_MCPServer.handle_tool_call()，形成「HTTP 网关 → MCP 工具调度 → 存储后端」的单向调用链。
- cloud/ 实现云端侧：agent.py 为云端 Agent 入口，server/mcp_server.py 暴露 MCP 工具集，storage/ 提供 memory_store.py（内存）与 state_store.py（持久化）两种后端抽象。
- local/ 实现本地侧：agent.py 为本地 Agent，client/mcp_client.py 通过 HTTP 调用云端 /mcp 端点，memory/instant_memory.py 与 state/state_cache.py 提供本地缓存层，与云端形成「近期记忆 + 远期沉淀」的分层。
- cnaa/ 是跨云端的共享契约层：models.py/schemas.py 定义统一数据模型与接口 Schema，tools.py/lifecycle.py/interaction.py 定义工具生命周期与交互协议，被 cloud/ 与 local/ 共同依赖。
- tests/ 覆盖云端存储、本地内存、核心模型、MCP 工具路由及 OpenClaw 集成；examples/openclaw_integration.py 演示外部 Agent 如何通过 HTTP/MCP 接入。
- pyproject.toml 声明项目名 cnaa、Python≥3.11 以及 mcp>=1.0.0 为唯一运行时依赖，dev 依赖 pytest/mypy/ruff，ruff 行宽 100、mypy strict 模式贯穿全项目。
